# P4.2 — ADMIN Payroll PDF

Source implementation only; build, compilation, database and runtime verification were not run.

- PDFKit 0.20.2 (production) and @types/pdfkit 0.17.7 (development) installed with operator approval.
- GET /api/admin/payroll/[id]/pdf runs on Node.js. Shared payroll API and detail service enforce active database-backed ADMIN authorization before reading snapshots. Only PUBLISHED slips can be rendered; DRAFT returns 409.
- UUID-only resource input. No monetary or employee data accepted from the browser. Filename uses validated UUID and server period, never employee text.
- PDF is generated in memory, returned as an attachment with application/pdf, private/no-store and nosniff. Nothing is written to public storage. Errors use the existing sanitized boundary without logging payloads.
- Local Noto Sans Regular/Bold are embedded using the existing traced assets/fonts paths. Deployment must preserve these assets and the application working directory. The fonts cover Indonesian/Latin text, not all Unicode scripts or emoji.
- Final design: A4 landscape with proportional local assets/images/company-logo.png at upper left, company snapshots beside it and PAYSLIP/pay period at upper right. Logo is traced for deployment; no asset is downloaded or replaced.
- Employee name uses large bold type, optional job title uses smaller secondary text, payment details form the adjacent column. All static labels/month names are English; database values remain untranslated, including bank/account strings and leading zeros.
- Two subtly shaded Earnings/Deductions headings with Description/Amount (IDR), right-aligned whole-IDR amounts, persisted subtotals and prominent TAKE-HOME PAY. Formatting uses BigInt, not floating point. Item ordering and zero amounts are preserved.
- Measured text wrapping and explicit line pagination handle long fields and up to the existing item limit. Continuation pages have a period header, repeated column headings when needed and page number. Items are never truncated; unusually long rows may continue across pages. Summary follows all components.
- Only the final page displays the centered footer beneath a thin separator: "This payslip was automatically generated by the payroll system of PT Bali Enneaphos. No signature is required."
- ADMIN modal PUBLISHED footer offers Download PDF with pending/error feedback. DRAFT stays disabled. X/Escape/backdrop and draft unsaved-change behavior are preserved. Client uses no-store fetch and temporary object URLs, revoked after download initiation or unmount; no persistent browser storage is used. The intentionally downloaded file remains under the operator's control.

## Manual acceptance

1. Active ADMIN downloads a published slip; USER, inactive/demoted ADMIN and unauthenticated requests are rejected. Direct DRAFT URL returns 409; invalid UUID returns 400 and absent UUID returns 404.
2. Compare all PDF values to published snapshots, including after changing employee profile/master components. Verify no database values or versions change on download.
3. Check zero amounts, empty category, missing bank/account, 18-digit amounts and exact Indonesian separators.
4. Check 100 items, long names/address/position, accented Latin text, asymmetric columns and multiple pages: no omitted/overlapping text, correct totals and footer.
5. Verify browser downloads on desktop/mobile, repeated-click prevention, session-expired/network/server-error feedback and modal X behavior.
6. Verify deployment includes both font files and company-logo.png, logo proportions, landscape print margins, English labels, and final-page-only footer. Endpoint headers must be private/no-store; no PDF is written into public or server storage.

Publish workflow, schema/migrations, Attendance/Overtime/Corrections remain unchanged. P4.3 USER access is not implemented.
